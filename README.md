# AStockQuant｜个人 A 股量化选股系统

面向个人使用的 Python 量化研究与选股项目，提供 Windows 中文桌面界面，将行情采集、策略筛选、回测验证和模拟交易整合到一个工作流中。

项目以周线趋势选股为核心，保留独立的尾盘短线策略。开发重点是让选股条件可解释、数据质量可检查、运行过程可续接，并通过 Git 提交和开发记录保存每次迭代。

## 核心策略

### 周线趋势与三级筛选

以 5、10、20 周均线向上排列、股价站稳 20 周均线、连续两周不破，以及高低点逐步抬高作为趋势判断基础；结合突破、回踩与成交量条件，将候选股分为 **预确认、确认、强确认**，方便进一步复核。

量能研究重点包括：突破周成交量达到过去 5 周均量的 1.5 倍，以及连续放量时第二周维持 1.2 倍以上。现有规则1、规则2、规则3和世坤因子研究方案保留并列验证，不因结构升级直接改动参数。

### 尾盘两日短线

在 14:30—15:00 观察候选，筛选沪深主板股票，排除 ST、创业板、科创板及北交所；结合价格、流通市值、均线、换手率、振幅、阶段涨幅和量能过滤，按当日涨跌幅降序排列。

主要条件包括：股价低于 13 元、流通市值低于 200 亿元、价格高于 10 日均线、涨幅低于 9%、振幅低于 6%、换手率低于 10%，并限制近期过快上涨与涨停记录。

持有期为买入后 T+1 至 T+2；达到 +5% 后启用从最高点回落 0.3% 的移动止盈，跌至 −5% 止损，最迟 T+2 尾盘退出。精确验证依赖分钟数据，并考虑 A 股 T+1 与无法成交的情况。

## 已有功能与当前边界

- Windows 中文桌面界面，支持行情与 K 线查看、策略筛选、回测和模拟交易。
- 全 A 股股票池检测入口，分别记录入选、未入选、策略排除、历史不足和数据失败等状态。
- 多行情源备用、日线与分钟缓存、增量更新、进度显示和扫描记录保存。
- 策略对照、结果导出及离线自检，便于核对策略变化和软件回归。
- 2026 年休市日期判断，避免要求获取不存在的节假日收盘行情。

全市场检测入口不等于全部证券的数据均已成功补齐；实际覆盖率以每次扫描报告为准。免费分钟历史覆盖有限，较早路径需要已保存的数据或外部导入。现阶段以选股研究、回测和模拟为主，真实券商自动下单仍属于后续计划。

## 技术与架构方向

使用 Python、PySide6 和 pandas，逐步将界面、应用服务、策略、回测、账户、撮合、风控与数据适配器分离。借鉴成熟项目的设计边界：

| 参考项目 | 借鉴方向 |
| --- | --- |
| [vn.py](https://github.com/vnpy/vnpy) | 引擎、应用与行情/交易网关边界 |
| [RQAlpha](https://github.com/ricequant/rqalpha) | 数据源、账户、撮合与回测接口 |
| [Microsoft Qlib](https://github.com/microsoft/qlib) | 因子研究与实验记录 |
| [easytrader](https://github.com/shidenggui/easytrader) | 后续券商适配研究 |

上述项目作为设计参考，不代表已经全部集成；引入外部代码或依赖时需遵守其许可证。

## Windows 使用方式

取得经过验证的双击安装包后，将程序文件解压到安装目录，首次运行 `1_第一次双击_安装并打开.bat`，以后运行 `2_以后双击_启动软件.bat`。

升级前关闭软件，保留原有行情缓存、扫描记录和模拟账户；程序代码与运行数据分开管理。开发恢复时先只读检查 Git 状态与进度记录，从未完成步骤继续，不通过重置或重建项目恢复。

## 后续重点

1. 提高全市场有效行情覆盖率，完善失败重试与数据质量检查。
2. 保持三级筛选结果可解释，并验证结构调整前后的结果一致性。
3. 完善含费用、滑点与成交限制的回测，积累分钟历史。
4. 在数据和验证流程稳定后，逐步研究券商接口。

本项目用于个人学习、研究和辅助筛选，不保证收益；历史回测和选股信号不能替代交易决策。
